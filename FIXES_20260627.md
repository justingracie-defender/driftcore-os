## The one design decision (made deliberately, not guessed): request → effect
The coordinator now translates a request into guard Effects in TWO tiers:
  * **Structural tag (primary, robust):** a tool/actuator is tagged with its
    real effect (`tool_effects={"turret_1": {Effect.LETHAL}}`). The tag wins
    over wording — a lethal-tagged tool blocks even with innocent phrasing.
  * **Keyword backstop (secondary, COARSE, FOOLABLE):** a tiny word list catches
    obvious lethal text when no tag applies. It is NOT real lethal detection;
    `test_lethal_effect_paths.py` includes a check that PROVES a euphemism
    ("neutralise the target") slips it — documenting the limit on purpose.

## New regression guard
`test_lethal_effect_paths.py` — proves lethal blocks via BOTH paths for the
right reason (`invariant == "no_lethal_action"`, not a crash), that benign
actuation is not over-blocked, and that the backstop's leak is a known limit.

## Honest limits (unchanged)
- Tested, not proven. The keyword backstop is leaky by design; the structural
  tag is only as good as deployments tagging their tools.
- These fixes were re-derived against the REAL code, not from memory of the
  earlier session — so this time the record travels with the fix.
